## 2. 题目总体目标

微网包含：

- 小区负载；
- 光伏发电；
- 储能设备；
- 与外部电网之间的购电通道。

核心目标是：

> 在满足负载供电和储能安全约束的前提下，通过合理安排**外网购电、储能充电、储能放电以及后续调整购电**，尽可能降低总购电费用。

四个问题不是互相独立的，而是逐步增加现实因素：

**问题1：确定性调度基准**  
→ **问题2：预测误差 + 紧急购电**  
→ **问题3：多时刻滚动预报 + 调整/违约成本**  
→ **问题4：实时波动电价**。

因此建议代码从一开始就采用统一的“数据层—预测层—优化层—仿真层—结果导出层”结构，使后续三问复用问题1的优化框架。

\]

# 4. 四个问题的简要要求

## 4.1 问题1：确定性单日最优购电

### 题目要求

假设：

- 每天电价相同；
- 每天小区负载相同；
- 已知一天的光伏预测功率；
- 微网供电不能低于负载；
- 0:00 与 24:00 储能电量相同。

需要在每天 0:00 制定当天计划购电策略，使购电费用尽可能低。

### 必须输出

1. 指定 6 个 10 分钟时间段的购电量；
2. 全天购电量；
3. 全天购电费；
4. 每 4 小时时段的储能总充电量、总放电量；
5. 0:00 与 24:00 储电量；
6. 完整填写 `result1.xlsx`。

### 本问作用

这是整个 C 题的**基础优化模型**。后面所有问题都应尽量复用本问的储能状态转移、功率平衡和购电费用模型。

---

## 4.2 问题2：预测误差与紧急购电

### 新增条件

- 每天电价曲线仍相同；
- 负载和实际光伏功率每天变化；
- 每天 0:00 先制定计划购电；
- 实际执行中如果计划供电不足，则进行紧急购电；
- 紧急购电价格为交易时刻正常电价的 **5 倍**；
- 普通购电费用仍按计划购电量计算。

### 关键变化

问题2不再是“已知当天真实负载和光伏后的确定性优化”，而应体现：

> **0:00 做预测 → 根据预测制定计划 → 用当天实际数据检验 → 不足部分紧急购电。**

结果从 2025.2.1 开始，意味着 1 月数据可以自然用于初始化、历史统计或预测模型训练/校准。

### 必须输出

- 2025.2.1—12.31 每天的计划购电量；
- 每天储能充放电情况；
- 每天 0:00 和 24:00 储电量；
- 所有发生紧急购电的连续时间段和总购电量；
- 论文中重点给出：
  - 2025.3.20
  - 2025.6.21
  - 2025.9.23
  - 2025.12.21
- 完整填写 `result2.xlsx`。

---

## 4.3 问题3：滚动光伏预报与调整购电

### 新增条件

每天可在以下时刻获得新的未来 24 小时整点光伏预测：

- 0:00
- 6:00
- 12:00
- 18:00

0:00 的预测用于制定“计划购电量”，后续预报可用于调整未来购电量。

若：

- 计划购电量 > 调整购电量：减少部分涉及 **50% 电价的违约成本**；
- 调整购电量 > 计划购电量：超出部分按 **1.5 倍电价**计费；
- 仍供电不足时还需紧急购电。

### 额外要求

不仅要给出策略，还要分析：

> **是否有必要使用 6:00、12:00、18:00 的新预报进行调整？**

也就是说，需要比较“调整带来的预测改进收益”和“调整/违约成本”之间的权衡。

### 必须输出

- `计划购电量`；
- `调整购电量`；
- 最终储能充放电；
- 最终紧急购电；
- 指定四个日期的论文表格；
- 是否采用后续预报的对比分析；
- 完整填写 `result3.xlsx`。

# 5. 建议的统一数学建模框架

## 5.1 时间离散

一天分为 144 个 10 分钟时段：

\[
\Delta t=\frac{1}{6}\text{ h}
\]

记时段为：

\[
t=1,2,\ldots,144
\]

建议优化模型内部统一使用 **kW 功率变量**，导出结果时再乘以 \(\Delta t\) 转为 kWh。

---

## 5.2 基本变量

可定义：

- \(P_t^{grid}\)：外网计划购电功率；
- \(P_t^{ch}\)：储能充电功率；
- \(P_t^{dis}\)：储能放电功率；
- \(E_t\)：储能电量；
- \(P_t^{emg}\)：紧急购电功率（问题2以后）；
- \(P_t^{adj}\)：调整后的购电功率（问题3以后）。

---

## 5.3 电力平衡

基础形式可写为：

\[
P_t^{grid}+P_t^{PV}+P_t^{dis}+P_t^{emg}
\ge P_t^{load}+P_t^{ch}
\]

问题1中：

\[
P_t^{emg}=0
\]

允许“≥”而不是强制“=”可以自然表示光伏弃电等情况；如团队决定显式建模弃光，则可增加弃光变量后改写为等式。

---

## 5.4 储能状态转移

若把充/放电功率定义为交流侧功率，可采用：

\[
E_t=E_{t-1}+\eta P_t^{ch}\Delta t-\frac{1}{\eta}P_t^{dis}\Delta t
\]

其中：

\[
\eta=0.9
\]

并满足：

\[
1200\le E_t\le10800
\]

\[
0\le P_t^{ch}\le5000
\]

\[
0\le P_t^{dis}\le5000
\]

问题1额外满足：

\[
E_{144}=E_0=6000
\]

> **需要建模手确认：**题目“充放电效率为90%”究竟解释为充电效率、放电效率均为 90%，还是一个统一的往返效率。上式采用“充/放电各 90%”的常见解释，但论文必须明确口径。

---

## 5.5 是否需要限制同时充放电

严格模型可以增加 0-1 变量，禁止同一时段同时充放电。

但考虑到：

- 充放电有损耗；
- 正常电价为正；
- 同时充放电通常不会降低费用；

建议第一版先建立 **线性规划 LP**，不引入二进制变量，运行后检查是否出现显著的同时充放电。

若出现不合理结果，再改为 MILP/SCIP 增加互斥约束。

这样可以明显降低比赛前期的代码复杂度和求解时间。

# 6. 每问的初始方案

## 6.1 问题1初始方案：确定性线性规划

### 输入

附件1：

- 固定电价 \(p_t\)；
- 固定负载 \(L_t\)；
- 单日光伏预测 \(G_t\)。

### 目标函数

最小化全天计划购电费：

\[
\min \sum_{t=1}^{144}p_tP_t^{grid}\Delta t
\]

### 约束

- 电力平衡；
- 储能状态转移；
- 储能上下限；
- 最大充放电功率；
- \(E_{24:00}=E_{0:00}\)。

### 实现建议

优先使用：

- `scipy.optimize.linprog` / HiGHS，或
- PySCIPOpt（若后续加入整数变量）。

问题1完成后需要立即形成一个可复用的 `optimize_day()` 函数。

---

## 6.2 问题2初始方案：日Ahead预测 + 日内实际仿真

问题2建议拆为两个层次。

### 第一层：0:00 预测

每天 0:00 只能使用此前已知数据，预测当天 144 个时段：

\[
\hat L_{d,t},\quad \hat G_{d,t}
\]

第一版不要直接上复杂深度学习模型，建议做三个层次：

**Baseline A：前一日同一时刻**

\[
\hat x_{d,t}=x_{d-1,t}
\]

**Baseline B：过去 7 天同一时刻加权平均/中位数**

用于快速获得稳定基线。

**Challenger：基于滞后特征的树模型或线性模型**

候选特征：

- 前1天同一时刻；
- 前2天同一时刻；
- 前7天同一时刻；
- 过去3/7/14天同一时刻均值；
- 星期信息；
- 一天中的时刻；
- 对光伏加入日照时段/历史同一时刻特征。

可考虑 LightGBM/XGBoost，但只有在基线明显不够时再上，优先保证全流程跑通。

### 第二层：计划优化

使用预测值：

\[
\hat L_{d,t},\hat G_{d,t}
\]

代入问题1优化器，获得：

- 计划购电 \(P^{plan}\)；
- 计划充放电策略。

### 第三层：实际仿真与紧急购电

将当天真实负载和真实光伏代入执行层。

若实际供电不足：

\[
P_t^{emg}
=
\max\{0,\ P_t^{load}+P_t^{ch}-P_t^{plan}-P_t^{PV}-P_t^{dis}\}
\]

紧急购电费用：

\[
C_t^{emg}=5p_tP_t^{emg}\Delta t
\]

### 强烈建议增加的风险控制

因为紧急购电是正常电价的 5 倍，单纯使用“均值预测”可能倾向于少买电。

建议在基线跑通后增加一个简单的**预测安全裕量/残差分位数**：

\[
\hat N_{d,t}^{safe}
=
\hat N_{d,t}+Q_\alpha(\varepsilon_t)
\]

其中净负载：

\[
N=L-G
\]

通过 1 月数据或滚动历史选择 \(\alpha\)，在“多计划购电成本”和“紧急购电成本”之间寻找平衡。

这通常比一开始堆复杂预测模型更直接影响最终费用。

## 6.3 问题3初始方案：滚动时域优化（Receding Horizon）

### 0:00

使用附件3的 0:00 光伏预测和问题2的负载预测，求出当天完整的：

\[
P^{plan}_{t}
\]

### 6:00 / 12:00 / 18:00

每次收到新光伏预测后：

1. 已执行时段锁定；
2. 获取当前实际储能电量；
3. 用最新光伏预测替换未来预测；
4. 重新优化剩余时段；
5. 得到新的调整购电量和充放电策略。

这就是标准的 **滚动时域优化 / Model Predictive Control 思想**。

### 光伏整点预报与10分钟调度的对齐

附件3只提供整点预测，而购电决策是 10 分钟级。

初版建议同时实现两种转换方式并比较：

1. **小时内保持常值**；
2. **相邻整点线性插值到 10 分钟**。

选取误差更小且逻辑更稳定的方式作为主方案。

### 调整成本的候选表达

记 0:00 计划购电量为 \(q_t^0\)，最终调整购电量为 \(q_t^a\)。

可定义：

\[
\Delta_t^+=\max(q_t^a-q_t^0,0)
\]

\[
\Delta_t^-=\max(q_t^0-q_t^a,0)
\]

一种自然的分段计费解释为：

当 \(q_t^a\le q_t^0\) 时：

\[
C_t=p_tq_t^a+0.5p_t(q_t^0-q_t^a)
\]

当 \(q_t^a>q_t^0\) 时：

\[
C_t=p_tq_t^0+1.5p_t(q_t^a-q_t^0)
\]

该形式仍可线性化为 LP。

> **需要建模手确认：**题目对“计划购电费用 + 调整购电相关费用”的文字存在解释空间，必须在正式编码前统一“减少部分是否仍支付原计划购电费”“多次调整是相对 0:00 原计划还是相对上一次调整”的口径。

### “是否需要使用后续预报”的实验

至少做以下策略对比：

| 策略 | 使用预报时刻 |
|---|---|
| S0 | 仅 0:00，不调整 |
| S1 | 0:00 + 6:00 |
| S2 | 0:00 + 6:00 + 12:00 |
| S3 | 0:00 + 6:00 + 12:00 + 18:00 |

比较：

- 总购电费用；
- 正常计划费用；
- 调整/违约费用；
- 紧急购电费用；
- 紧急购电总量；
- 光伏预测误差。

最后不是简单地说“预测越新越好”，而应根据**总费用最低**判断是否值得调整。

## 6.4 问题4初始方案：统一价格接口后重新求解

代码中不要把附件1固定电价写死，而统一使用：

```text
price[date, time]
```

问题1—3固定电价时，各天引用同一日内曲线；问题4则直接读取附件4的实际日内价格曲线。

然后分别复用：

- 问题2预测 + 计划 + 紧急购电流程 → `result4-2.xlsx`；
- 问题3滚动调整流程 → `result4-3.xlsx`。

### 重点分析

波动电价下通常会出现更明显的储能套利：

- 低价时充电；
- 高价时放电；
- 高价时段尽量避免紧急购电；
- 调整购电的价值也会随交易时刻价格变化。

因此论文中可重点比较：

- 固定价格 vs 波动价格的总成本；
- 充放电时段变化；
- 紧急购电变化；
- 问题3中滚动调整价值是否发生变化。

> **需要建模手确认：**附件4的当日未来价格在 0:00 是否视为已知。若题意要求“实时价格仅到达时才能知道”，则问题4还需要增加价格预测；若视为当天价格曲线已知，则直接作为确定输入即可。第一版建议先完成“当日价格曲线已知”的基准计算。

# 8. 开始编码前必须先确认的模型口径

以下内容不要由代码手自行拍板，应尽快由建模手/团队统一，并写入论文假设。

1. **90%效率的具体定义**  
   是充电和放电各 90%，还是整体往返效率 90%。

2. **问题2中 0:00 的信息集**  
   是否明确要求只能利用过去数据预测当天负载和光伏，不能直接使用当天真实值。

3. **问题2以后的日末 SOC**  
   是否仍要求每天 \(E_{24}=E_0\)，还是允许 SOC 跨日连续传递。题目只在问题1明确提出相等约束。

4. **紧急情况下能否实时改变储能充放电**  
   是严格执行 0:00 制定的储能计划，仅缺口紧急购电，还是可以先实时调整电池后再紧急购电。

5. **问题3减少计划购电量的计费方式**  
   50%是取消部分的违约金，还是在原计划购电费用之外另加 50%。

6. **问题3多次调整的基准**  
   6/12/18 点的调整，是始终相对 0:00 原计划计费，还是相对上一次已调整计划计费。

7. **问题3的储能策略是否也允许随新预报滚动调整**。

8. **问题4未来电价是否视为已知**  
   若不是已知，则需要单独加入价格预测模块。

可直接向建模手转述：

> “请先统一确认效率口径、问题2以后SOC是否跨日、紧急购电前能否实时调整储能、问题3的50%/1.5倍调整费如何计费及多次调整的比较基准、问题4当天未来价格是否视为已知。代码结构会根据这些口径预留接口，但不自行修改模型定义。”

# 9. 数据与模板中必须特别注意的实现细节

## 9.1 时间索引不是普通的“0:00开始”格式

附件1及全年附件的时间标签从约 **0:10** 开始，一直到 **0:00+1**。

同时结果模板中的购电时段以 `0:10-0:20` 开始，末尾还包含跨日的 `0:00(+1)-0:10(+1)` 类时段。

因此第一天编码时必须先完成一个**时间索引对齐单元测试**：

```text
附件时间戳 -> 模型 t -> 结果模板时段
```

不能凭习惯直接把附件第一条记录解释为 `0:00-0:10`。

## 9.2 功率与电量单位不能混

附件数据为 kW，结果购电量和充放电量为 kWh。

所有 10 分钟功率都需要：

\[
Energy=Power\times\frac{1}{6}
\]

## 9.3 问题2/3/4必须防止未来数据泄漏

例如计算 2025-03-20 的 0:00 计划时，只能使用在 2025-03-20 0:00 前已知的信息。

不能为了预测方便直接用整年的真实数据拟合后再回代，否则论文中的“0:00制定计划”失去意义。

建议采用 **walk-forward / expanding-window** 测试。

## 9.4 附件3是小时级预测，购电是10分钟级

必须写清楚并统一：

```text
forecast issue time
→ forecast horizon 1...24 h
→ absolute timestamp
→ 10-min interpolation
```

这部分最容易出现 1 小时错位。

## 9.5 不要修改结果模板结构

原则：

- 不增删工作表；
- 不改表头；
- 不调整日期顺序；
- 只填写要求的单元格；
- 最终单独写 `validator.py` 检查空值、负数、SOC越界、时间长度和费用一致性。

# 10. 推荐的验证指标

## 10.1 预测层

建议至少统计：

- MAE；
- RMSE；
- WAPE；
- 光伏白天时段 MAE/WAPE；
- 净负载误差 \(L-PV\)。

但最终模型选择不应只看预测误差，还应看**最终购电总成本**。

## 10.2 调度层

必须自动检查：

- 每个时段供电是否满足负载；
- SOC 是否始终处于 `[1200,10800]`；
- 充/放电功率是否 ≤5000 kW；
- 问题1是否满足首尾 SOC 相同；
- 问题2以后紧急购电是否正确补足缺口；
- 各费用分项求和是否等于总费用；
- 结果文件单位是否全部为 kWh/元。

## 10.3 问题3策略比较

建议最终形成如下总表：

| 策略 | 正常购电费 | 调整费 | 紧急购电费 | 总费用 | 紧急购电量 |
|---|---:|---:|---:|---:|---:|
| 仅0:00 |  |  |  |  |  |
| +6:00 |  |  |  |  |  |
| +6:00,+12:00 |  |  |  |  |  |
| +6:00,+12:00,+18:00 |  |  |  |  |  |

用此表直接回答“其他时刻预报是否值得采用”。

## 最终一句话概括

C题可以统一理解为：

> **先预测未来净负载，再通过储能把低价电搬到高价时段；当预测存在误差时用高价紧急购电兜底；当获得新光伏预测时，比较重新调整计划所节省的紧急购电成本与调整违约成本；最后在实时波动电价下重复这一策略。**
