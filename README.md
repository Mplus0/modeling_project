# 数学建模竞赛项目

本仓库用于数学建模正式比赛期间的资料整理、数据分析、模型实现、结果输出与团队协作。

当前仓库已清理历史模拟赛的赛题、数据、代码和运行结果，并使用 `.gitkeep` 保留必要的空目录。正式比赛开始后，请按下述目录约定存放新赛题相关内容，避免将不同用途的文件混放。

## 目录说明

| 目录 | 用途 |
| --- | --- |
| `赛题及预设实现方案/` | 存放正式赛题、附件说明、思路草稿、任务拆分和预设实现方案。 |
| `data/raw/` | 存放比赛提供的原始数据。原则上只读，不直接修改原文件。 |
| `src/` | 存放可复用的核心代码，如数据处理、模型构建、求解、评价与可视化模块。 |
| `scripts/` | 存放可直接运行的流程脚本，如数据检查、模型训练、求解和结果生成入口。 |
| `outputs/figures/` | 存放论文和汇报使用的图片。 |
| `outputs/forecast/` | 存放预测类任务的中间结果与最终结果。 |
| `outputs/logs/` | 存放程序运行日志和求解器日志。 |
| `outputs/metrics/` | 存放模型评价指标、统计结果和验证报告。 |
| `outputs/schedule/` | 存放调度或优化类任务的求解结果。 |
| `tmp/` | 存放可随时清理的临时文件和调试产物。 |

`.gitkeep` 仅用于让 Git 保留空目录。目录中加入正式文件后，可以保留或删除对应的 `.gitkeep`，不会影响项目运行。

## 环境配置

建议使用 Python 3.11，并在独立的 Conda 环境中安装依赖：

```bash
conda create -n modeling_project python=3.11
conda activate modeling_project
python -m pip install -r requirement.txt
```

当前依赖包括：

- `pandas`、`numpy`：数据处理与数值计算；
- `openpyxl`：Excel 数据读写；
- `matplotlib`：结果可视化；
- `scipy`：科学计算与常用算法；
- `pyscipopt`：基于 SCIP 的数学规划求解。

比赛中如引入新的第三方库，请同步更新 `requirement.txt`，确保其他成员能够复现运行环境。

## 使用流程

1. 将赛题原文、附件说明和初步方案放入 `赛题及预设实现方案/`。
2. 将官方原始数据放入 `data/raw/`，不要覆盖或手工修改原始文件。
3. 在 `src/` 中编写核心功能，在 `scripts/` 中建立清晰的运行入口。
4. 将程序生成的图表、指标、日志及其他结果分别写入 `outputs/` 下对应目录。
5. 使用 `tmp/` 保存无需长期保留的中间文件，重要结果应及时移入 `outputs/`。
6. 提交代码前检查文件路径、依赖版本和运行说明，确保项目可以从根目录复现。

## 建议约定

- 所有脚本均从项目根目录运行，避免使用仅在个人电脑上有效的绝对路径。
- 原始数据与生成结果分开保存，数据清洗后的文件应使用新文件名输出。
- 脚本建议按执行顺序编号，例如 `01_check_data.py`、`02_preprocess.py`、`03_run_model.py`。
- 图表和结果文件使用含义明确的名称，并在论文中记录其生成脚本及参数。
- 随机算法应固定随机种子；关键实验应记录参数、指标和运行时间。
- 临时文件、缓存和 Office 自动生成文件不应提交到仓库。

## 注意事项

- 比赛开始前，请确认赛题、数据和成果文件是否允许上传至远程仓库；如包含未公开或受限材料，应使用私有仓库或仅在本地协作。
- 大型数据集、模型文件和高分辨率结果图可能不适合直接纳入 Git，请根据比赛规则和团队协作方式统一管理。
- `outputs/forecast/` 与 `outputs/schedule/` 可按实际选题使用；若正式赛题不涉及预测或调度，可将其用于相近类型的结果，或由团队统一调整目录名称。
